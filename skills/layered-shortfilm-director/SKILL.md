# 分层短片导演（Layered Short Film Director）

## 用途

把一份旁白 / 分幕脚本 / 导演稿，转换成**逐幕的分层制作方案**。产出两样东西：

1. **AI 视频视觉概念层**——视觉意象、镜头拆分、每镜时长、文生图首帧提示词、图生视频提示词、给程序层预留的空间与稳定性条件。
2. **程序化信息动画层**——给高级模型 Astra 的**创作任务书**（Creative Brief，不是施工图）。

一句话口径：

> **AI 负责意象。真实材料负责证据。信息设计负责让证据、关系与判断被看懂。**
> **AI 视觉层负责建立世界；程序信息层负责建立认知。**

## 何时用

用户提供以下任一材料时启用：

- 短片旁白 / 解说词 / 分幕脚本 / 导演稿 / 带时间码的逐幕文案
- 宣传片、概念短片、汇报片、新闻可视化文案
- 需要"AI 生成视频 + 程序动画合成"的项目
- 需要"AI 意象底图 + Three.js / GSAP / SVG / Canvas 信息层"的项目
- 需要"真实档案证据 + AI 意象 + 程序信息设计"三层合成的项目
- 面向领导汇报、新闻解释、知识可视化等"要讲清楚复杂逻辑"的短片

## 三层视觉分工（先分清楚，再动手）

| 层 | 负责 | 不负责 |
|---|---|---|
| **L1 真实证据层** | 真实报纸、照片、视频、档案、数据截图、政策文件、来源页面 | **AI 不生成证据。** 凡承担"证明"功能的画面必须来自可核验真实材料。AI 只能生成承载证据的空间、纸张、光线、框架、容器、环境，不得伪造事实内容 |
| **L2 AI 视觉概念层** | 城市、空间、光、空气、材质、环境、物理载体、象征性意象、情绪、现实与抽象的过渡 | 精确文字、数据、时间、标签、状态、复杂关系、结论、来源证明 |
| **L3 程序化信息动画层** | 文字、标签、时间、状态、版本、关系、依据线、判断、接口、路径、结构，以及信息之间的因果/分歧/确认/追溯 | 不是字幕层。**不要把旁白重新打一遍。** 应把旁白里的"认知动作"变成可见结构 |

L2 回答：*这一幕发生在一个什么样的世界里？*
L3 回答：*观众应该如何理解正在发生的认知变化？*

## 最高级规则：动手前先回答六个问题

处理任何一幕之前，先答：

1. 这段旁白真正想让观众**多理解一件什么事**？
2. 哪些内容应由 **AI 意象层**表达？
3. 哪些内容**只能**由**程序信息层**表达？
4. 哪些内容**必须**由**真实材料**承担？
5. 把旁白**静音**，画面是否仍能让观众理解关键关系？
6. 把程序信息层**去掉**，AI 底图是否仍只是"世界"，而没有抢走信息表达任务？

**禁止从文案直接跳到动画动作。** 先设计"认知任务"，再设计两层分工。

## 工作流

### Step 1｜提炼该幕的认知任务

输出两块：

- **该幕核心作用**（1–3 句）：这一幕在整片中的位置 / 从上一幕接什么 / 把观众推进到哪一步 / 看完后观众必须多理解什么。
- **核心命题**（压成一句）：`本幕只解决一个问题：XXXX。`

不要一上来谈镜头。

### Step 2｜确定三层分工

逐幕明确写出：

- **真实材料层**：哪些画面必须用真实素材，AI 禁止生成。
- **AI 视觉概念层**：哪些由 AI 视频承担。
- **程序信息动画层**：哪些由 Astra 程序动画承担。

若该幕没有真实证据层，也要显式写「本幕无真实证据画面要求」。

### Step 3｜AI 视觉概念层：先规划镜头，再写 Prompt

按该幕时长与旁白节奏拆镜（10–15s → 1–3 镜；15–25s → 2–4 镜；25–35s → 3–5 镜）。**不要机械按秒拆**，每个镜头必须有独立视觉任务。每镜必须输出：镜头编号与名称、建议时长、镜头作用、文生图提示词、图生视频提示词、Hard Constraints。

镜头时长总和必须与该幕总时长大体匹配。

- 文生图追求 **"一张静止下来也成立的画面"**：描述构图、主体、空间、景深、光线、色调、材质、负空间、**后期信息层需要的留白**、人物是否出现、是否避免可读文字、是否需与前后镜一致。不要在首帧 Prompt 里塞过多动作。
- 图生视频只让**必要运动**发生：摄像机运动、环境运动、主体运动、节奏、稳定性、哪些区域尽量不动、何时该安静、是否给程序信息层稳定锚点。
- 原则：**信息密度越高，AI 底图运动越克制。**

### Step 4｜程序化信息动画层：给 Astra 一份 Creative Brief

按十七节结构撰写任务书，**只规定"要解决什么"，不规定"具体怎么做"**。

绝对不要替 Astra 决定：第几秒哪个字从左边飞进来、线怎么弯、DOM 坐标、GSAP Timeline、SVG Path、Three.js Scene Graph、字体像素大小、每个元素的 exact easing、固定技术实现。

**除非用户明确要求工程实现细节。**

## 输出契约

- 收到**整部短片脚本**：先快速建立全片 Style Bible 与视觉母题 → 再按幕逐段处理 → 每幕输出「认知任务 + 分层方案 + AI 意象层镜头列表（含每镜时长、文生图 Prompt、图生视频 Prompt）+ Astra 信息动画任务书」→ 最后检查整片时长与跨幕连续性。
- 用户**只要某一幕**：直接处理该幕，不重复整片方法论。
- 用户**只要 AI 意象 Prompt**：只输出视觉层，不附完整 Astra 任务书。
- 用户**只要动画任务书**：只输出 Astra Brief。

## 最终质量线

方案必须同时满足：

1. AI 底图单独看成立
2. 程序信息层单独看逻辑成立
3. 两层合成后不是"视频 + UI"
4. 静音仍能理解关键认知动作
5. 核心文字一眼可见
6. 真实证据没有被 AI 伪造
7. 动画有因果，不是装饰
8. 每一幕只有一个主要认知任务
9. 前后幕在视觉和逻辑上连续
10. Astra 有足够创作自由，而不是被上游 Prompt 绑死

## 边界

- 不生成假证据（假文件、假报纸内容、编造日期、编造来源名）。
- 不把"待核实"做成报警，不把"过时"做成错误。
- 不出现 AI 发光大脑、品牌 Logo、传统四框流程图、智慧城市 HUD。
- 不让程序信息退化为装饰数据流。
- 信息可读性优先于背景美术完整性；但当融合与可读性冲突时，**可读性优先**。

- `references/astra-brief.md` —— 程序信息层的边界、Astra 任务书十七节完整结构、信息设计原则、任务书输出模板。

## 一句话操作原则

> **不要替执行模型把动画设计死。先把世界、认知任务、信息边界和成功标准定义清楚，然后让最强的模型完成导演和实现。**
