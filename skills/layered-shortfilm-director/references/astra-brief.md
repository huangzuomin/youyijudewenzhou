# 程序化信息动画层 & Astra 任务书

来源：`layered-shortfilm-director` 原始规范第 7、8、9、11 节。

---

## 1. 层的归属

程序信息层由高级模型 **Astra** 负责创作和实现。

本 Skill **不能把 Astra 降级成施工模型**。

不要替 Astra 决定：

- 第几秒哪个字从左边飞进来
- 哪条线具体怎么弯
- DOM 坐标
- GSAP Timeline
- SVG Path
- Three.js Scene Graph
- 字体具体像素大小
- 每个元素 exact easing
- 固定的技术实现

除非用户明确要求工程实现细节。

默认任务是：

> **给 Astra 一个足够好的 Creative Brief，而不是施工图。**

## 2. 信息设计原则

### 2.1 不把旁白做成字幕

优先问：这句话对应的"认知变化"是什么？

例如旁白：

> 同时发生，不等于存在因果。

不要只把这句话打出来。应该先让：

`两个事件试图建立因果关系 → 关系被阻止。`

文字只负责命名这个判断。

### 2.2 状态优先于特效

任何动画先定义：初始状态 → 变化 → 新状态。

而不是：飞入、发光、放大、粒子。

### 2.3 一个镜头一个主动作

允许环境和次级动效存在。但任何时刻只能有一个主要视觉动作。

### 2.4 World Response

重要的信息行为应对视觉世界产生后果。例如：

- 缺少来源 → 关系无法落点
- 关系不成立 → 连线被阻止
- 来源冲突 → 保持分叉
- 核验完成 → 结构稳定
- 版本更新 → 旧版本退入历史层
- 过时 → 保留但降为历史状态

### 2.5 信息动画的核心不是"文字怎么动"

而是：

> **观众怎么理解。**

## 3. Astra 任务书必须包含的十七节

对每一幕的信息动画层，生成一份完整任务书。必须包含以下部分。

### 一、任务定义

包括：项目、段落、时间、时长、任务类型、最终用途。

明确：

> 本任务规定"要解决什么"，不规定"具体怎么做"。

### 二、这一幕在整部片中的位置

说明：前面发生了什么 / 为什么现在需要这一幕 / 它如何推进整片逻辑 / 它要给下一幕留下什么。

### 三、核心认知问题

用一句话写：

> 本幕需要解决的核心认知问题是：XXXX。

### 四、观众看完必须得到的理解

列出 3–6 条。**必须是认知结果，不是动画结果。**

- 错误：看到一根线分叉
- 正确：观众理解"来源存在分歧时，系统不会强行合并成一个答案"

### 五、旁白

完整保留该幕旁白。不要擅自改写，除非用户要求改文案。

### 六、必须出现的信息

明确哪些文字 / 概念 / 状态不能丢。例如：

事实、知识、判断、v1、v2、已过时、待核实、找到、理解、验证、调用。

不要规定具体布局。

### 七、必须完成的认知行为

用逻辑链描述必须发生什么。例如：

`新记录进入 → 不直接改写旧结论 → 审阅 / 核验 → 新版本成立 → 旧版本保留`

不要提前规定具体动画形式。

### 八、与 AI 意象层的关系

必须说明：

- **AI 意象层负责什么**
- **Astra 信息层负责什么**

强调：两层不是"背景 + UI"。目标是：

> 信息像原本就属于这个世界一样生长出来。

但当融合与可读性冲突时：

> **信息可读性优先。**

### 九、色彩与色调

默认沿用影片整体 Style Bible。必须说明：AI 底图的综合色调 / 信息层普通色 / 次级信息色 / 核心信息色 / 强调色原则 / 禁止的色彩套路。

例如：避免科技蓝、避免红绿灯审批逻辑、避免彩虹分类、强调色极少量使用。

### 十、字体与信息突出要求

必须强调：

> **核心文字是视觉对象，不是 UI 注释。**

影片属于视频观看场景，不是电脑后台。所以核心信息应：大、清楚、醒目、稳定、有阅读时间、会议大屏可瞬间识别。

不必规定具体 px。判断标准：

> 第一次观看的人是否一眼看到。

对于刻意应"小"的编辑批注，要明确例外。

### 十一、信息层与底图冲突时的优先级

明确允许 Astra：局部压暗背景 / 降低背景运动 / 调整景深 / 使用克制衬底 / 利用遮挡 / 调整信息位置。

原则：

> **信息可读性优先于背景美术完整性。**

### 十二、贯穿视觉母题

如果整片已有依据线、一支笔、纸张、时间层、版本层或其他视觉母题，必须说明其语义。**不能让母题退化为纯装饰。**

### 十三、创作自由

明确告诉 Astra，以下内容自行决定：

视觉隐喻、空间结构、运动语法、文字动画、构图、镜头、2D / 2.5D / 3D、Three.js / GSAP / SVG / Canvas 技术路线、Shared Object Transition、World Response、Attention Design。

如果有更好的表达：

> **优先采用自己的方案。**

### 十四、不可突破的边界

只写真正重要的负面约束。例如：

- 不生成假证据
- 不把待核实做成报警
- 不把过时做成错误
- 不出现 AI 发光大脑
- 不出现品牌 Logo
- 不做传统四框流程图
- 不做智慧城市 HUD
- 不让程序信息退化为装饰数据流

### 十五、与上一幕 / 下一幕的衔接

说明：哪些对象应该继承 / 哪些结构应该退场 / 下一幕需要什么状态。

### 十六、Astra 实现前先提交导演方案

默认要求：**Astra 不直接编码。**

先提交一份简短导演方案，至少回答：

1. 如何理解这一幕的核心命题
2. 采用什么视觉隐喻
3. AI 意象层与信息层如何协作
4. 关键文字如何建立层级
5. 关键认知行为怎样发生
6. 如何与前后幕衔接
7. 技术实现方向
8. 可能的风险

**先审理解，再实现。**

### 十七、最终验收标准

至少从以下维度生成验收项：

| 维度 | 检查什么 |
|---|---|
| 认知测试 | 静音后是否仍能理解核心逻辑 |
| 信息测试 | 必须出现的信息是否清楚 |
| 文字测试 | 核心字是否足够醒目 |
| 因果测试 | 动画是否真正表达了"为什么发生" |
| 分层测试 | AI 底图和信息层是否分工明确 |
| 融合测试 | 信息是否像属于同一个世界，而不是网页浮在视频上 |
| 克制测试 | 是否存在不必要的运动 |
| 真实性测试 | 是否有 AI 虚构证据 |
| 思想测试 | 看完后是否自然得到该幕最终结论 |

验收标准尽量写成：

> 如果 X 看不出来，则失败。

避免模糊的"高级、好看、有质感"。
